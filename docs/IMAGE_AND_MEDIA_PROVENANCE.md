# Dasha News — Image & Media Provenance

## Objective

Every published visual must have a defensible provenance record. No paid image API is required.

## Preferred image sources

Use, in order where suitable:
1. Public-domain or clearly licensed repositories.
2. Wikimedia Commons and similar sources with explicit license metadata.
3. Other free/licensed image sources already permitted by their terms.
4. Publisher/official social posts or media only when the intended use is permitted by the source's terms, license, or an allowed embed/link mechanism.
5. Dasha-generated neutral illustrative artwork using local/free tooling when no suitable licensed factual image exists.
6. A typography/location card when no safe image exists.

## Twitter/X and social media

Do not make a paid Twitter/X API a dependency.

Do not automatically download and republish arbitrary posts or images simply because they are publicly visible.

For an official/public social post:
- retain the original post URL;
- retain account identity;
- record timestamp;
- prefer an allowed embed/link when appropriate;
- use an image only when the usage basis is documented;
- never imply Dasha owns the image.

If terms/rights are unclear, use the post as a source/evidence link and create a neutral Dasha visual instead.

## News channels and publisher media

Publisher images, YouTube thumbnails, television screenshots, and article photographs are not automatically free to republish.

Where rights are unclear:
- link/attribute the source;
- do not silently copy the image into Dasha;
- use a licensed/public-domain/generated visual instead.

## Required media metadata

Every image/media asset should support:
- source URL
- original media URL if different
- publisher/creator
- license/usage basis
- attribution text
- retrieval time
- checksum where practical
- asset type
- whether embedded, linked, cached, or generated
- story id
- takedown/review status

## Image selection

Prefer factual relevance over sensationalism. Never generate a photorealistic image that could be mistaken for actual evidence of a real event unless it is prominently labeled as illustrative.

## Zero-cost generation

A local image generation tool/model may be used if it fits the Azure VM's resources. Otherwise use clean typography/location/category cards. Do not add a paid image-generation API merely to fill a card.
